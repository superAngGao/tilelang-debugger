# 源码访问接入：问题归因与统一修正方案

2026-10-09。用户要求先统一分析、设计，再修改，避免边跑边加例外。本方案写于本次结构调整之前；此前通过的结果仅作为回归依据。现已按本方案实施并完成回归，最终结果见[结构调整验收](source-access-validation.md#统一修正后的最终验收)。

## 已发现的问题

| 现象 | 根因 | 应归属的职责 |
| --- | --- | --- |
| copy 区域调用名误写为 tl.region | 把文档称谓当成实际前端对象表示，适配散落在 emitter | 前端对象适配 |
| 测试要求 shared，实际是 shared.dyn | 用预期名称代替对象真实属性 | 前端事实读取与测试契约 |
| 循环临时名改变 n | TileLang eager 对 Var／Buffer 的普通赋值会原地命名；别名不是无副作用操作 | 符号绑定 |
| 打印宏参数把 n、stride 都命名为 value | 宏参数复用同一 bind 规则；与循环问题同根因 | 符号绑定 |
| 避开 Name 赋值后，解析和插入各自判断是否建别名 | 局部规避导致规则重复，也没有统一保证混合参数的求值顺序 | 源码求值计划 |
| buffer 下标出现在 atomic／address／自定义宏参数中 | AST Load 上下文不等于一次普通读取 | 源码操作语义 |
| 掩码内索引包含读取、调用或可能未定义的除法 | “打印表达式”可能增加求值或改变求值条件 | 求值边界 |

根因依据是固定 TileLang eager builder 的 bind／macro_arg：普通 Var／Buffer 绑定调用 IRBuilder.name；meta_var 在 bind_immutable 中解包，不重命名。仅在源码上判断 ast.Name 不足以决定真实前端对象的绑定行为。

## 统一流程与实现

1. 源码分析生成确定的观察语义及循环参数求值计划。位置参数、关键字参数按原顺序各求值一次；插入器消费该计划，不再自己判断 Name 特例。循环迭代身份使用同一计划中的参数引用。
2. 新增薄的 frontend 适配层。bindings 适配器对已有 Var／Buffer 使用前端 meta_var 引用，保留身份和名称；其他表达式保留正常赋值，让前端按原机制构造一次绑定。此规则用于所有循环参数，不按源码写法猜测对象类型。
3. frontend/access 负责将 Buffer、BufferLoad、BufferRegion 和 copy 前端 region 统一为逻辑操作数；复用 copy 的前端归一化，读取实际 scope／dtype／shape／stride，不发出搬运、同步或目标读取。
4. emitter 只把操作数元组编码为现有 int64 记录。原符号通过闭包引用，不作为标量宏形参重新绑定。字段顺序由协议模块集中定义，适配器和报告共用。
5. report 只解释已验证的完整元组。候选索引、活动条件、区域边界、采集完整性分别保留；数值 reference 与访问报告分别核对。

访问语义仍限制在明确支持的元素读写和 T.copy；原子操作、地址取得和自定义 buffer 宏不按 AST Load 猜测。对于会增加内存读取／副作用的表达式，继续要求显式 scalar 绑定，不做另一套 lowering 分析，也不恢复旧 trace。

## 不变量与验证

- **绑定不变**：真实前端实验检查原 n／stride 的名称、身份、buffer shape／stride 关系在插桩前后保持；覆盖直接变量和返回已有变量的调用。
- **求值不变**：位置／关键字混合参数的构建侧调用次数与顺序保持；解析与插入都使用同一参数计划。
- **操作事实正确**：用真实前端对象检查整 buffer、标量元素、显式区域、copy 头地址推断及 shared.dyn；字段数、顺序与报告一致。
- **无新增目标访问／同步**：小测例继续检查前端目标 BufferLoad、copy、同步数量；这仅是测试，不是产品准入门禁。
- **实际输出正确**：重新运行同一套 H200 小测例、动态 shape／stride／stream 测例和未修改的 TileOPs 测例；核对独立期望索引、数值 reference、输出逐位一致、sanitizer 与报告扰动检测。
- **回归范围稳定**：CPU／TIR 全套通过；不为了重构扩大支持范围或放宽已识别的语义边界。

# 用户指定源码路径修正

用户指出输入文件名必须由用户指定。本次修正 `run`/`trace` 的源码路径输入与来源报告，不能将它表述为已解除所有用户 kernel 限制。

1. 两条命令增加可选 `--source FILE`，相对路径以调用时 cwd 为基准。未指定时使用已有观察配置的 `source`，相对路径以配置文件所在目录为基准。该字段必须是非空字符串；不再限制等于 `kernel.py`，也不再推断 driver 同级文件。CLI 显式参数优先，保存实际生效的绝对路径。
2. 先读取配置、解析用户路径，再读取该文件。保留 CLI 原输入/config 原内容与 effective source 元数据；失败信息应指出用户选择的文件。实际源码内容摘要仍参与当前契约校验。内容不匹配时正确报告既有契约不支持，不能回退到另一个 kernel.py。
3. worker 的 `source/kernel.py` 是现有独立执行沙箱中的内部快照名，不是用户输入的文件名要求。本次保持该执行归档/既有受审驱动的 `from kernel import ...` 约定，不改变源码内容、同步/布局校验或 driver 契约。可将已支持的 kernel 文件复制到任意名称/路径并显式选择，worker 必须运行该文件的快照。用户自定义包导入/JIT、修改驱动后的哈希限制仍属未完成的通用接入；README 必须明说，不能用别名伪装完成包接入。
4. run/point/request 记录 original source 的实际绝对路径；离线数值报告与 access 报告显示该路径和行号。旧产物没有字段时保留兼容显示，不更改旧证据。
5. 更新 TileOPs 接入探测：不再依赖已修复的 FileNotFoundError。将实际上游路径作为 `--source`，把解析到的代表观察点转成现有 config 结构，真实 CLI 读到上游源码后，只把严格匹配的“无受审源码/driver 契约”分类为 unsupported，其他错误仍失败。该探测没有绕过准入，也没有获得中间数据。

验收：CPU 覆盖 CLI 转发、路径优先级、不同 cwd/config/driver 目录、相对/绝对/空格路径、缺失/空路径、错误内容不回退、来源报告；旧 CPU 回归。H200 使用内容未变但改名/移至独立目录的 GELU kernel，通过真实 run 和 trace 采集、数值/reference/输出位一致检查，验证源文件路径进入产物与报告；原固定输入调用兼容。六次 TileOPs 真入口探测仍应在契约处明确拒绝，不能把后续通用接入标成完成。

先独立设计审阅，再实施、独立代码审阅及 H200 验收。产品不新增算子、源码哈希或 CUDA 白名单项。
